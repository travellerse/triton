Instruction availability, via clang builtins (correct syntax, no hand-asm typos):
  $ clang --target=amdgcn-amd-amdhsa -mcpu=gfx1031 -S builtins2.cpp
      -> selected v_permlanex16_b32   (OK on gfx1031)
      -> ds_bpermute path compiled OK
  $ same with -mcpu=gfx942
      -> error: '__builtin_amdgcn_permlanex16' needs target feature gfx10-insts
  => v_permlaneX16 exists on the GFX10 family; it is gated on feature
     "gfx10-insts", which gfx942 lacks and gfx1031/gfx1100 have.

  $ clang -cc1-style hand-written v_wmma_f32_16x16x16_f16 ... -mcpu=gfx1031
      -> error: instruction not supported on this GPU (gfx1031)
     same mnemonic on -mcpu=gfx1100 -> "invalid operand for instruction"
     (opcode recognized, only my operands were wrong)
  => WMMA 16x16x16 f16 is NOT in the gfx1031 ISA; it is RDNA3+. This is a
     hardware limit, not a Triton gap. (Graded: observed assembler capability
     message; the operand-syntax difference between the two targets is what
     makes this readable.)

  Negative control that FAILED: `llc -mattr=+bogus-feature-xyz` was silently
  accepted on gfx1031/gfx1100/gfx1250, so -mattr is NOT a valid probe for
  feature existence. Any conclusion drawn from -mattr is excluded below.
